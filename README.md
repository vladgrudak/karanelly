# KaraNelly Space — новый сайт

Статический многостраничный сайт фотостудии. Без сборки, без CMS и без зависимостей:
чистый HTML + CSS + немного ванильного JS. Загружается на любой хостинг как есть.

## Структура

```
karanelly/
├── index.html          Главная (открывается по адресу /)
├── space/index.html    Пространство (о зале)      → /space/
├── gallery/index.html  Галерея: новогодний блок + постоянная → /gallery/
├── events/index.html   Мероприятия и мастер-классы  → /events/
├── booking/index.html  Бронирование (виджет appEvent) → /booking/
├── contacts/index.html Контакты, карта и видео     → /contacts/
├── privacy/index.html  Политика конфиденциальности → /privacy/
├── disk/index.html     Пояснение для персональных ссылок на фото
├── 404.html            Страница ошибки (+ редирект /disk/…)
├── robots.txt
├── sitemap.xml
├── .htaccess           Кэш, сжатие, 404 (для Apache; на REG.RU не читается)
├── deploy.py           Выкладка на хостинг по FTP
├── .deploy.env.example Образец настроек FTP
└── assets/
    ├── css/
    │   ├── fonts.css   @font-face для локальных шрифтов
    │   └── style.css   Все стили
    ├── js/
    │   ├── main.js     Меню, хедер, появление блоков, скелетон календаря
    │   └── gallery.js  Лайтбокс: клавиатура, свайпы, фокус
    ├── fonts/          Cormorant Garamond + Golos Text (woff2, кириллица)
    ├── img/            WebP в трёх размерах, OG-картинка, иконки
    └── video/          Видео: маршрут (MP4 + постер) и карусель мастер-классов в events/
```

## Локальный просмотр

```bash
cd karanelly
python3 -m http.server 8000
# открыть http://127.0.0.1:8000
```

Структура папок рассчитана на «чистые» адреса: `/space/`, `/gallery/`, `/contacts/`.
При локальном просмотре через сервер они работают так же, как на хостинге.
Просто открыть `index.html` двойным кликом тоже можно, но тогда не сработают
относительные пути в некоторых браузерах — лучше через сервер.

## Хостинг

Сайт живёт на виртуальном хостинге REG.RU, тариф «Хост-Лайт», панель ISPmanager:
**https://karanelly.space/**

- домен, DNS, хостинг и почта — в одном аккаунте REG.RU;
- корень сайта: `/var/www/uXXXXXXX/data/www/karanelly.space`, по FTP — `www/karanelly.space`;
- HTTPS — бесплатный Let's Encrypt: выпускается и продлевается в ISPmanager;
- SSH на тарифе нет, поэтому выкладка — по FTP;
- PHP и база данных не нужны: сайт полностью статический.

## Как менять контент

- **Тексты** — прямо в HTML, каждый блок подписан комментарием.
- **Фото** — лежат в `assets/img/`: `g01…g20` (постоянная экспозиция) и `ny01…ny09`
  (новогоднее оформление), каждая в размерах `-640`, `-1100`, `-1600`.
  Замените файл с тем же именем и размером — вёрстка подхватит автоматически.
  Если меняете пропорции, поправьте `width`/`height` у `<img>`, чтобы не было скачков.
- **Цены и правила** — список того, что нужно подтвердить у владельца, лежит рядом с проектом
  в `content-notes.md` (файл намеренно не входит в репозиторий: это внутренние заметки).
- **Сезонный блок** («Новогоднее оформление») — секция `.season` на странице `booking/index.html`,
  её стоит обновлять или убирать вручную.

### Сезонное оформление

На `/gallery/` блок «Новогоднее оформление» идёт первым, ниже — постоянная экспозиция
под подписью «Круглый год». Блок — отдельная секция с `id="ny-title"`: когда оформление
сменят, её можно удалить целиком (вместе с фотографиями `ny*`) или заменить на новую.

Фото для сезона снимаются вертикально, кодируются в WebP 640/1100/1600 по ширине.
Главное фото на первой странице — тоже сезонное: `hero-m-720/1080` для телефона
(вертикальный кадр) и `hero-1280/1920/2560` для десктопа (обрезка 16:9).

## Видео на странице контактов

Ролик `How_to_find_us.mov` (исходник 80 МБ, HEVC, 816×1326, 46 с) перекодирован для веба:

| Файл | Формат | Размер |
|---|---|---|
| `assets/video/how-to-find.mp4` | H.264, 720×1170, 30 fps | 7,2 МБ |
| `assets/video/how-to-find-poster.jpg` | JPEG 720×1170 | 64 КБ |

Формат один — MP4 с H.264: его играют все браузеры и телефоны. WebM/VP9 пробовал,
но на этом материале (зерно, пасмурная погода) он вышел тяжелее MP4, поэтому оставил
только MP4 — меньше файлов, проще поддерживать.

Звук удалён: в исходнике дорожка была пустой (средний уровень −91 dB), все подсказки
впечатаны в кадр. Видео грузится только при нажатии (`preload="metadata"` + постер),
поэтому на скорость страницы почти не влияет.

Если будете менять ролик — держите те же пропорции 720×1170 и кодируйте так:

```bash
ffmpeg -i new.mov -vf "scale=720:-2,fps=30" -c:v libx264 -crf 30 -preset slow \
  -pix_fmt yuv420p -movflags +faststart -an how-to-find.mp4
```

## Видео с мастер-классов

Шесть вертикальных роликов для карусели на `/events/` лежат в `assets/video/events/`
(`ev-video-01…06.mp4` + постеры). Все перекодированы в 720×1280, H.264, 30 fps, без
метаданных, со `faststart`.

Звук выровнен по громкости: исходники расходились на 20 дБ (−34…−14 LUFS), все
приведены к −16 LUFS через двухпроходный `loudnorm` (linear), AAC 128 kbps.

Лента работает как Apple «highlights»: на телефоне активная карточка стоит по центру экрана, у каждой карточки своя светлая
подложка, а лента тянется от края до края. Под роликами один таймлайн из точек.
На телефоне показ стартует сам, когда лента попадает в кадр; на компьютере —
по кнопке play. Ролик доигрывает — точка сжимается, включается следующий.
Звук один на всю ленту: кнопка «Звук выключен / включён» действует на все ролики,
а по умолчанию всё играет без звука.

Если добавляете ролик — сначала измерьте, потом кодируйте с измеренными значениями:

```bash
ffmpeg -i in.mp4 -af loudnorm=I=-16:TP=-1.5:LRA=11:print_format=json -vn -f null -
ffmpeg -i in.mp4 -vf "scale=720:1280:force_original_aspect_ratio=decrease,pad=720:1280:(ow-iw)/2:(oh-ih)/2,fps=30" \
  -c:v libx264 -crf 30 -preset slow -pix_fmt yuv420p -movflags +faststart \
  -c:a aac -b:a 128k -ar 44100 -ac 2 -map_metadata -1 out.mp4
```

## Виджет бронирования

Встроен через `<iframe>` на `booking/index.html`:

```
https://appevent.ru/widget/embeded?widget_key=…&hall_id=9494
```

Ограничения, которые важно знать:

- стилизовать содержимое iframe нельзя — это чужой домен; можно только оформить рамку вокруг;
- виджет сам перестраивается под ширину iframe: на телефоне — компактная сетка
  на 7 колонок, на компьютере — широкая таблица. Поэтому iframe растянут на 100%
  без фиксированной минимальной ширины, горизонтальной прокрутки нет;
- если appEvent поменяет `widget_key` или `hall_id`, правьте `src` в одном месте — `booking/index.html`.

Пока календарь грузится, поверх него показывается скелетон; он скрывается по событию
`load` у iframe или через 9 секунд.

## Технические решения

**Производительность.** Фото — WebP в трёх ширинах, `srcset`/`sizes`, `loading="lazy"`
для всего, кроме первого экрана. Герой предзагружается через `<link rel="preload">`
с нужным вариантом для мобильных и десктопа (`<picture>` + `media`).

**Шрифты** — self-hosted, 18 файлов woff2 с `unicode-range` (латиница/кириллица),
`font-display: swap`. Внешних запросов к Google Fonts нет — быстрее и без передачи данных.

**Адаптив** — mobile-first, контрольные точки 560 / 768 / 860 / 900 / 1040 / 1280 px.
Проверено на 360, 390, 768, 1024 и 1440 px: горизонтального переполнения нет.

**Доступность.** Ссылка «к содержанию», `aria-expanded` у меню, `inert` для скрытого меню,
focus trap в меню и лайтбоксе, управление стрелками и Esc, `prefers-reduced-motion`,
осмысленные `alt` у всех фото.

**SEO.** Уникальные `title`/`description`, Open Graph, `canonical`, JSON-LD
`PhotographyBusiness` на главной, `sitemap.xml`, `robots.txt`, семантическая разметка
(`header`, `main`, `section`, `figure`, `dl`).

## Выкладка на хостинг

GitHub — источник правды и история правок, хостинг — только «витрина».
Правки делаются локально, проверяются локальным сервером и выкладываются по FTP.

### Первая настройка

1. Скопировать `.deploy.env.example` в `.deploy.env` и заполнить:
   - `FTP_HOST` — `karanelly.space` (или IP сервера);
   - `FTP_USER` — логин хостинга, вида `u1234567`;
   - `FTP_PASS` — пароль хостинга;
   - `REMOTE_DIR` — папка сайта на FTP, обычно `www/karanelly.space`.
2. Ставить ничего не нужно: скрипт на Python 3, он уже есть в системе.
3. Проверить путь: `DRY_RUN=1 ./deploy.py` — покажет список файлов без загрузки.
   В целевой папке должен лежать `index.html`.

`.deploy.env` в git не попадает — пароль хранится только на компьютере.

### Обычная выкладка

```bash
./deploy.py
```

Скрипт заливает только изменённые файлы (сверяет размер и время модификации через FTP)
и создаёт недостающие папки. Таймаут сетевых операций — `FTP_TIMEOUT` в `.deploy.env`
(по умолчанию 120 секунд; если обрывается на видео — поставьте 180–300). По умолчанию
**не удаляет** ничего на хостинге; для зеркала один-в-один: `DELETE=1 ./deploy.py`
(осторожно: удалит всё, чего нет локально, кроме исключений).

Исключения: `.git`, `.github`, `.deploy.env`, `deploy.py`, `README.md`,
`.DS_Store`, `.well-known` (там живёт сертификат).

Альтернатива скрипту — FileZilla: хост `karanelly.space`, логин `uXXXXXXX`,
пароль хостинга, порт 21, «FTP over TLS», заливать в `www/karanelly.space`.

### Порядок правок

1. Правим файлы локально.
2. Смотрим: `python3 -m http.server 8000` → http://127.0.0.1:8000
3. Коммитим: `git add -A && git commit -m "Что изменилось"`.
4. Выкладываем: `./deploy.py`.
5. Проверяем https://karanelly.space/ и изменённую страницу.

Откат: вернуть файлы из нужного коммита (`git checkout <коммит> -- <файл>`
или `git revert`) и снова `./deploy.py`.

## Домен, DNS и HTTPS

Домен `karanelly.space` зарегистрирован в REG.RU. NS — `ns1.hosting.reg.ru` и
`ns2.hosting.reg.ru`, A-запись указывает на IP хостинга (сейчас `31.31.196.187`).

В ISPmanager у сайта выбран бесплатный сертификат Let's Encrypt и включён
редирект HTTP → HTTPS. Сертификат продлевается автоматически.

Проверка:

```bash
dig +short A karanelly.space
curl -I https://karanelly.space/
```

## Редирект /disk/

Ссылки на фотографии персональные: `karanelly.space/disk/<slug>` ведут на
`https://p9lp025rjm2x.wfolio.pro/disk/<slug>`. Файла с таким путём нет, поэтому
nginx отдаёт 404, а `404.html` скриптом перебрасывает на Wfolio, сохраняя путь.

Чтобы это работало, в ISPmanager включена своя страница ошибки:
Сайты → ⋯ у сайта → «Страницы ошибок» → 404 → `/404.html`.

`/disk/` без хвоста показывает пояснение, что ссылка персональная.

## Чего в проекте больше нет

- **GitHub Pages** отключён, `CNAME` и `.nojekyll` удалены. GitHub остаётся
  хранилищем кода и истории.
- **Cloudflare** — зона удалена, DNS снова в REG.RU.
- **`.htaccess`** оставлен для переносимости, но на этом хостинге nginx отдаёт
  статику напрямую и файл не читает. Правила `space.html → /space/`, своя 404 и
  кэш-заголовки здесь не работают — редиректы и страницы ошибок настраиваются
  в ISPmanager.
